# Функциональные требования к MVP

## Use Case: Генерация задания преподавателем
*   **Актор:** Преподаватель.
*   **Предусловия:** Преподаватель авторизован в системе и находится на странице генерации заданий (`/generate`).
*   **Основной сценарий:**
    1. Преподаватель выбирает тему задания из выпадающего списка (например, "Основы JS").
    2. Преподаватель выбирает тип задания (тест с вариантами ответов или теоретический вопрос).
    3. Преподаватель нажимает кнопку «Сгенерировать».
    4. Система отправляет запрос к API на Node.js.
    5. Система получает сгенерированное задание и отображает его на экране в виде карточки.
*   **Альтернативный сценарий:** Ошибка сервера. Если API недоступно, на экране появляется сообщение: «Не удалось сгенерировать задание, попробуйте позже».

## Границы MVP (Minimum Viable Product)
*   **Входит в MVP (реализовано на этапе каркаса):** Настроенный роутинг между страницами, отображение UI-заглушек (форм, карточек), использование компонентов из библиотеки.
*   **Не входит в MVP (перспективы разработки):** Реальная интеграция с Node.js, работа с базой данных, реальная генерация текста заданий и логика проверки ответов.
